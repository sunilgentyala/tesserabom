Inventories

Two inventories auditors keep asking for

Which cryptography is really running here, and how ready is it for post-quantum migration? Which AI models and MCP servers are on these machines? The SIEM gives you excellent telemetry, and the 4.14.x release notes searched in November 2026 show no native answer to either.

C

CBOM

Certificates, TLS endpoint posture, SSH key exchange and crypto libraries, flagged for quantum vulnerability. CycloneDX 1.6.

AI

AI-BOM

Local model files (hashed, header-checked), MCP server configs, and local AI runtimes. Credentials are never read, only key names.

Δ

Drift and downgrade

A baseline remembers every asset. Alerts fire on changes, and on downgrades such as TLS 1.3 falling to 1.2.

✓

Signed attestations

Each BOM can be wrapped in a DSSE envelope signed with Ed25519, so an inventory can be proven untampered.

Pipeline

How it works

A collector runs on each endpoint, writes the BOMs, and prints one JSON line per finding. The SIEM reads those lines through the command wodle and applies 19 rules tagged for PCI DSS, DORA and NYDFS lookups.

Scancertificates, TLS, SSH, models, MCP
Comparebaseline drift and downgrades
AttestCycloneDX plus DSSE signature
AlertSIEM decoder, rules, dashboards
Install

Quick start

pip install .

tesserabom keygen --dir /etc/tesserabom
tesserabom scan --out /var/lib/tesserabom/out \
  --baseline /var/lib/tesserabom/baseline.json \
  --sign-key /etc/tesserabom/tesserabom-signing.key \
  --tls-port 443

tesserabom verify out/cbom.dsse.json --pub /etc/tesserabom/tesserabom-signing.pub
tesserabom diff old/cbom.json new/cbom.json

SIEM content (decoder, rules, agent snippet) is in the siem/ folder and in each release as a zip. scripts/logtest_docker.sh repeats the manager test.

How it differs

Found in a November 2026 search that was broad but not exhaustive: to our knowledge, no open-source project combines endpoint collection, CBOM plus AI-BOM, a downgrade baseline, signed attestations and SIEM-native rules. This is not a claim to be first.

Transparency

Honest limits

  • Post-quantum TLS status depends on what the probing client can negotiate.
  • SSH status uses sshd -T only as root.
  • tesserabom never launches MCP servers, so it pins the configured launch spec but cannot see a server change what it advertises.
  • Attestations use Ed25519, a classical signature.
  • The 5.x series and a remote agent reporting to a separate manager are untested.
  • Compliance tags are lookup aids, not statements of compliance.
